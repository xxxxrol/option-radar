# رادار زخم الأوبشن

ماسح لعقود الأوبشن على الأسهم الأمريكية الكبيرة. الخادم يجلب سلاسل الأوبشن من ياهو في الخلفية، ويحسب زخم كل عقد، ويعرضها في واجهة عربية، ويرسل تنبيهات تيليجرام حتى والصفحة مغلقة.

بيانات ياهو غير رسمية ومتأخرة نحو 15 دقيقة. الأداة للفرز فقط وليست توصية بيع أو شراء.

## النشر على Render (الأسهل)

1. أنشئ مستودعاً على GitHub وارفع محتوى هذا المجلد (بما فيه `package-lock.json`).
2. في Render: New ثم Blueprint، واختر المستودع. سيقرأ `render.yaml` تلقائياً.
3. أدخل المتغيرات عند الطلب:
   - `ACCESS_PASSWORD`: كلمة سر للدخول (مهمة، لأن الرابط عام). اسم المستخدم أي شيء.
   - `PUBLIC_URL`: رابط الموقع بعد إنشائه، ويُضاف للتنبيهات.
   - `TELEGRAM_BOT_TOKEN` و `TELEGRAM_CHAT_ID`: اختيارية، شرحها أدناه.
4. انتظر البناء، ثم افتح الرابط.

**مجاني (الإعداد الافتراضي في `render.yaml`):** الخطة المجانية في Render تعطي 750 ساعة شهرياً، وتنام الخدمة بعد 15 دقيقة بلا طلبات، وعندها يتوقف الفحص والتنبيهات. لإبقائها مستيقظة أنشئ حساباً مجانياً في UptimeRobot أو cron-job.org، وأضف فحصاً كل 5 دقائق على الرابط `https://اسم-خدمتك.onrender.com/healthz` (هذا الرابط مفتوح بدون كلمة سر). 750 ساعة تكفي خدمة واحدة تعمل طوال الشهر.

حدود المجاني: قد يعيد Render تشغيل الخدمة في أي وقت، وبعد كل إعادة تشغيل يتجاهل الخادم أول فحص بصمت فقد تفوتك تنبيهات تلك الدقائق. وإن فاتت إحدى الدعوات تستغرق الخدمة نحو دقيقة لتستيقظ. وسياسات المجاني قد تتغير، فراجع صفحة Render المجانية.

للاستقرار الأعلى بدّل `plan: free` إلى `plan: starter` (نحو 7 دولار شهرياً) ولا تحتاج مُنبّهاً.

يعمل المشروع أيضاً على أي استضافة تدعم Docker (Railway، Fly.io، VPS): الصورة جاهزة في `Dockerfile` وتستمع على `PORT`.

## التشغيل على جهازك

```bash
npm install
npm start          # ياهو، يفتح على http://localhost:8080
npm run dev        # مزود تجريبي بأرقام مولّدة، للتطوير فقط
npm test
```

يحتاج Node 22 أو أحدث.

## تنبيهات تيليجرام

1. في تيليجرام افتح `@BotFather` وأرسل `/newbot`، وانسخ الرمز إلى `TELEGRAM_BOT_TOKEN`.
2. أرسل أي رسالة للبوت الجديد، ثم افتح `https://api.telegram.org/bot<TOKEN>/getUpdates` وانسخ `chat.id` إلى `TELEGRAM_CHAT_ID`.
3. أعد تشغيل الخدمة.

يرسل الخادم تنبيهاً عن كل عقد جديد يتجاوز الشروط (الافتراضي: زخم 80، حجم/OI من 1.5، حجم من 1000، سترايك ضمن 8% من السعر، استحقاق خلال 30 يوماً). عدّلها بمتغيرات `ALERT_*` في `.env.example`. أول فحص بعد كل تشغيل يسجّل العقود الموجودة بصمت حتى لا تصلك رسائل عن عقود قديمة. التنبيه يُرسل مرة واحدة لكل عقد في اليوم.

## الإعدادات المهمة

| المتغير | الافتراضي | المعنى |
|---|---|---|
| `SYMBOLS` | 27 سهماً وصندوقاً | الرموز التي يفحصها الخادم في الخلفية |
| `REFRESH_SEC` | 180 | فاصل الفحص أثناء السوق المفتوح |
| `CLOSED_REFRESH_SEC` | 1800 | فاصل الفحص خارج ساعات السوق |
| `REQUEST_DELAY_MS` | 350 | مهلة بين الرموز لتجنب حظر ياهو |
| `SCAN_MAX_DTE` / `SCAN_MAX_EXPIRIES` | 45 / 6 | أبعد استحقاق وعدد التواريخ لكل سهم |
| `MAX_SYMBOLS` | 60 | أقصى عدد رموز، بما فيها ما يضيفه المستخدم من الواجهة |

إذا كتبت رمزاً جديداً في الواجهة يضيفه الخادم ويجلبه فوراً. كل رمز يضيف عدة طلبات لياهو في كل دورة، فلا تكثر منها.

## كيف يعمل

- `providers/yahoo.js`: جلب السعر وسلاسل الأوبشن عبر حزمة `yahoo-finance2`.
- `lib/score.js`: حساب الزخم (حجم/OI 30%، قيمة التداول 25%، الحجم 15%، قرب السترايك 12%، السبريد 10%، قرب الاستحقاق 8%).
- `server.js`: دورة الجلب، التخزين المؤقت، واجهة `/api/scan`، الحماية بكلمة سر، تحديد المعدل، التنبيهات، `/healthz`.
- `public/`: الواجهة.

## حدود يجب معرفتها

- ياهو قد يرفض الطلبات أو يغيّر شكل بياناته دون إنذار. الخادم يتراجع ويعيد المحاولة عند الرفض، ويعرض آخر بيانات ناجحة مع تنبيه في الواجهة، لكن لا ضمان لاستمرار المصدر.
- الأحجام متأخرة وتعود لجلسة اليوم، وOI يتحدث مرة يومياً.
- حجم/OI العالي يدل على نشاط غير معتاد، ولا يكشف هل التداول شراء أم بيع.
- العطل الرسمية للسوق غير مضمّنة في فحص ساعات السوق.
- هذا المشروع لم يُجرَّب على ياهو الحقيقي قبل التسليم. اختُبرت الواجهة والخادم والتنبيهات والحماية بمزود تجريبي، واختُبر تحويل بيانات ياهو ببيانات مسجلة. شغّله مرة وراقب السجلات (`fetch_failed`) في أول يوم.
